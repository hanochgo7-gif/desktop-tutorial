# Lucid content schema

All learning content is data: JSON files under `content/`, validated by `tools/validate-content.mjs`
(`npm run validate`). The app never hard-codes lessons, so new lessons, scenarios or expressions are
added by adding files and listing them, without touching application code.

```
content/
  taxonomy.json          levels, skills, topics (grammar/vocab/writing skill ids), error types
  curriculum.json        the lesson sequence (generated by tools/curriculum-outline.mjs); each level's
                         final_assessment is a full writing brief: task (one line), instructions
                         (Bilingual, Hebrew up to B1), stage, kind, min_words/max_words, audience?,
                         topics?[] (Bilingual, optionally `assignment`: an assignment whose fictional
                         source pack the topic uses) and required_elements[] (Bilingual)
  lessons/<id>.json      one file per lesson
  placement.json         placement-test item bank
  real-life/scenarios.json   travel, social and workplace scenarios
  real-life/slang.json       expressions dictionary
  writing/exercises.json     writing-lab exercises (stages 1-10)
  writing/assignments.json   advanced argumentative assignments
  writing/rubric.json        the 12-category rubric and band descriptors
  (generated by tools/build-content-index.mjs, never edited by hand; see "Generated files" below)
  real-life/index.json, real-life/scenario/<id>.json, writing/index.json, writing/task/<id>.json,
  centers/{read,listen,speak}.json, pool/<level>.json
```

## Bilingual text

`{ "en": "...", "he": "..." }`. Hebrew is **required** on instructions and explanations for Pre-A1 to A2,
recommended at B1, optional at B2, and normally absent at C1-C2 (where an optional `he` glossary can
still be given). The app shows Hebrew according to the learner's support setting, which fades with level.

English learning material (sentences, options, passages, answers) is always plain strings.

## Lesson (`content/lessons/<id>.json`)

| Field | Type | Notes |
|---|---|---|
| `id`, `level`, `title_en`, `title_he`, `topics` | | must match `curriculum.json` |
| `minutes` | int | realistic time (current lessons: 15-40); the daily plan splits long lessons across days |
| `objectives` | Bilingual[] | 2-4 can-do statements |
| `warmup` | Bilingual | one line that activates prior knowledge |
| `explanation` | Block[] | see blocks below; concise, example-first |
| `examples` | `{en, he?, note?, note_he?}[]` | 5-10 model sentences; `note_he` is the note in Hebrew (shown under it while Hebrew support is on) |
| `vocab` | Vocab[] | 6-15 items added to the learner's notebook |
| `hebrew_pitfalls` | `{en, he, error_type}[]` | L1-transfer traps relevant to this lesson |
| `exercises` | Exercise[] | 10-16, easy to hard, mixing types and skills. Must include at least one input exercise (`read`, `listen` or `dictation`) and one free-production exercise (`write` or `speak`): input, brief explicit focus, controlled practice, free production, feedback (research C2, D13-D15). |
| `review` | `{key_points: Bilingual[]}` | 3-5 points shown at the end |
| `completion` | `{pass_score}` | fraction of auto-graded points needed (default 0.7) |

Blocks: `{type: "p" | "rule" | "tip" | "warning", en, he?}`, `{type: "table", headers: string[], rows: string[][]}`,
`{type: "examples", items: [{en, he?, note?}]}`.

Vocab: `{word, pos, he, def, example, example_he?, ipa?, collocations?: string[], level}`.

Hebrew glosses state the claim (validator rule, UX round 3 BL-2): a `he` or `*_he` string may quote short English
tokens but not more than one English sentence or more than 8 English words, and an `en` string has no Hebrew. Errors
at Pre-A1 to B1, warnings above.

## Exercises

Common fields: `id` (unique in the lesson), `type`, `skill` (taxonomy skill), `topic?` (taxonomy topic;
defaults to the lesson's first topic), `prompt` (Bilingual instruction), `explanation` (Bilingual, shown
after answering: *why* the answer is right), `hint?` (Bilingual, offered before revealing), `error_type?`
(taxonomy error type recorded when the learner gets it wrong).

| type | fields | graded by |
|---|---|---|
| `mcq` | `question`, `options[]` (3-4), `answer` (index), `option_feedback?` `{index: Bilingual}`, `option_errors?` `{index: error_type}` | exact |
| `tf` (inside `read` only) | `statement`, `answer` (bool) | exact |
| `gap` | `text` with one or more `___`, `answers` (array per blank of accepted strings), `word_bank?`, `wrong_feedback?` `[{match, feedback, error_type?}]` | normalised match, typo tolerance |
| `order` | `tokens[]` (in correct order; shuffled at runtime), `answers?` (extra accepted orders as sentences) | exact sequence or accepted sentence |
| `match` | `pairs` `[[left, right], ...]` (4-6) | all pairs |
| `categorize` | `categories[]`, `items` `[{text, category}]` | per item |
| `transform` | `source`, `answers[]`, `wrong_feedback?` | normalised match |
| `correct` | `sentence` (contains the error), `answers[]`, `error_type` (required) | normalised match |
| `listen` | `audio_text` (spoken by TTS), `question`, `options[]`, `answer` | exact; transcript shown after |
| `dictation` | `audio_text`, `answers[]` | word accuracy >= 0.85 |
| `speak` | `target`, `focus?` (Bilingual note), `error_type?` | practice, never graded: shows what speech recognition heard (if available), the learner can try again, self-rate or skip ("Can't speak right now"); excluded from the lesson score |
| `read` | `title?`, `passage`, `questions[]` (each an `mcq`, `tf` or `gap` without its own `skill`) | per question |
| `write` | `task` (Bilingual), `min_words`, `max_words?`, `must_include?[]`, `model_answer`, `checklist` (Bilingual[]) | submission + automatic checks; AI rubric when configured |

Normalisation for typed answers: case, surrounding spaces and final punctuation are ignored; curly and
straight apostrophes are equal; standard contractions are equivalent to their full forms (`don't` = `do not`),
so authors list each answer once. A one-letter slip in a word of 5+ letters is accepted as "almost - check
the spelling".

## Placement (`content/placement.json`)

`{ items: [{id, level, skill, type: "mcq" | "gap" | "listen", ...exercise fields}] }`, at least 10 items per
level from Pre-A1 to C2, mixing vocabulary, grammar, reading and listening. Items are written so a
correct answer is strong evidence of ability at that level (no trick questions, one clearly best answer).

## Real-life scenarios (`content/real-life/scenarios.json`)

`{ scenarios: [Scenario] }`:
`id`, `module` (airport | hotel | restaurant | transport | shopping | social | emergency | work), `title_en`,
`title_he`, `level`, `situation` (Bilingual), `goal` (Bilingual), `partner_role`, `phrases`
`[{en, he, register: "polite" | "neutral" | "casual", variant?: "US" | "UK", note?}]`,
`model_dialogue` `[{speaker: "partner" | "you", text}]`,
`practice` `[{partner, options: [{text, verdict: "best" | "ok" | "poor", feedback: Bilingual, error_type?}], model_replies[], keywords[]}]` (`error_type` names the taxonomy error a weaker option shows, so analytics do not guess),
`roleplay` `{persona, complication, opening_line}` (used by AI roleplay when configured),
`culture?` (Bilingual[]), `variants?` `[{us, uk, note?}]`, `sensitive?` (see below).

## Expressions (`content/real-life/slang.json`)

`{ entries: [{id, term, meaning_en, meaning_he, usage (Bilingual), formality: "very informal" | "informal" |
"neutral", region: "US" | "UK" | "both" | "AU", example_dialogue: [{speaker, text}], mistakes: Bilingual[],
avoid_when: Bilingual, warning?: Bilingual, related?: string[], level, sensitive?}] }`.

`sensitive?`: `("offensive" | "vulgar" | "sexual" | "alcohol")[]`, on a scenario or an expression whose subject
or wording is one of these. Lucid has no minimum age, so a flagged item is not shown to learners under 16
(`js/core/age.js`, applied in `js/core/content.js` for every screen); everyone else sees it as before, with its
`warning`, which a flagged expression must have. No item is flagged today (November 2026).

## Writing (`content/writing/*.json`)

Exercise: `id`, `stage` (1-10), `level`, `kind` (sentence-correction | sentence-transformation |
paragraph-completion | argument-construction | thesis-development | evidence-evaluation | counterargument |
outlining | essay | editing | summarization | critical-response | research | timed), `title_en`, `title_he`,
`instructions` (Bilingual), `input_text?`, `items?` (auto-graded exercises, same schema as lessons),
`min_words?`, `max_words?`, `time_limit_min?`, `focus` (rubric category ids), `scaffold?` (Bilingual[]),
`checklist` (Bilingual[]), `model_answer?`.

Assignments add `prompt`, `source_pack?` `[{title, kind: "illustrative", text}]` (invented, clearly
labelled material: no real-world statistics are fabricated), `required_elements[]`, `word_range [min, max]`
and `exemplar?` `{outline, annotated_paragraph}`.

## Generated files (`tools/build-content-index.mjs`)

The sources above stay the truth. So that a screen downloads only what it shows (docs/perf/content.md), the
generator cuts them into small files; run it after editing a scenario, a writing task or a lesson, then
`node tools/build-manifest.mjs`. Two runs give byte-identical files. `npm run validate` and
`tests/unit/content-index.test.mjs` fail when a generated file differs from what its source gives now
(`node tools/build-content-index.mjs --check` lists them).

| File | Holds | Read by |
|---|---|---|
| `real-life/index.json` | `{scenarios: [{id, module, level, title_en, title_he, goal, n_practice}]}`, in source order | Today, lesson end, Real life, Conversations, Practice, onboarding, profile |
| `real-life/scenario/<id>.json` | one scenario, as in `scenarios.json` | the scenario screen |
| `writing/index.json` | `{exercises: [row], assignments: [row]}`; row = `{id, stage, level, kind, title_en, title_he, word_range?, min_words?, max_words?, time_limit_min?, n_items?, prompt?}` (`n_items` = the number of `items`) | Today, lesson end, Writing lab, essay (titles, stages) |
| `writing/task/<id>.json` | one writing exercise or assignment, as in its source | the essay screen; a final task's topic pack |
| `centers/{read,listen,speak}.json` | `{lessons: {id: {id, level, title_en, title_he, topics}}, items: [{lesson, i, ex}]}`: the `read`, `listen` + `dictation` and `speak` exercises, in curriculum order (`i` = the exercise's index in its lesson) | Reading, Listening, Speaking |
| `pool/<level>.json` | `{lessons: {id: {id, level, topics, pitfalls}}, items: [{lesson, ex}]}`: the auto-graded exercises of the level's lessons, in lesson-file order | drills and level checks (`js/core/pool.js`) |

Ids become file names, so they use letters, digits, `.`, `_` and `-` only (the generator stops on any
other id). The index and per-item files belong in the offline list (contract C-2: tools/build-manifest.mjs lists
them once the delivery lane's change is in); the centre and pool files are cached
when first used. When a generated file cannot be loaded (offline, never cached), `js/core/content.js` falls
back to the source file, and the centres, drills and level checks fall back to the lessons on the device.
