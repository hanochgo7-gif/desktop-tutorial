**עמודים שלא נבנו בכוונה** (כדי לא ליצור עמודים ריקים):
- *איכות ובטיחות* — אין מידע מאומת (תקנים, הסמכות, נתוני בטיחות). יוקם כשיתקבל.
- *עמוד יזמים נפרד* — עמוד בנייני המגורים כתוב ליזמים; עמוד נוסף היה משכפל אותו.
- *מאמרים* — תוכנית תוכן ב-`seo.md`; לא נכתבו מאמרים לפני שיש ידע מהחברה (מחירים, תהליכים) כדי לא להמציא.

## מסלולי המרה

```
לקוח פרטי:  גוגל "קבלן לבניית בית פרטי" → private-homes → מה להכין → רשימת בדיקה → טופס (בית פרטי מסומן)
יזם:        המלצה/חיפוש שם → דף הבית → בנייני מגורים → שאלות (ליווי בנקאי) → טופס / טלפון
גוף ציבורי: חיפוש שם / רשימת קבלנים → מבנים ציבוריים → "מה הסיווג שלכם" → טופס עם מספר מכרז
המלצה:      שם החברה → דף הבית → שלט האתר בפוטר (רישום, טלפון) → טלפון
```

## הטופס

שדות חובה: **שם, טלפון** בלבד. אופציונלי: סוג הפרויקט (בחירה), מיקום, הודעה.
ולידציה בצד הלקוח (שם ≥ 2 תווים, טלפון ישראלי 9–10 ספרות, כולל +972), הודעות שגיאה כתובות ומקושרות (`aria-describedby`), פוקוס לשדה הראשון השגוי, הודעת סטטוס נקראת לקורא מסך.
הגנת ספאם: שדה מלכודת + זמן מילוי מינימלי בצד הלקוח; בצד השרת (HG OS): טוקן, מלכודת והגבלת קצב (`crm/supabase/migrations/009_web_intake.sql`).

**שלושה מצבי שליחה**, לפי מה שמוגדר ב-`tools/config.py`:
1. `HGOS_TOKEN` מוגדר → הפנייה נכנסת כליד ב-HG OS, עם מקור הקמפיין (אחרי הסכמה לעוגיות).
2. רק אימייל מוגדר → נפתחת הודעת אימייל מוכנה עם כל הפרטים.
3. שום דבר → מצב תצוגה: הטופס בודק את הפרטים ואומר בכנות שלא נשלח. בראש כל עמוד מוצגת הודעת "גרסת תצוגה".
