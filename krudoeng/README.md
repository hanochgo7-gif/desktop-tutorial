# קרודו הנדסה · האתר החדש

אתר סטטי בעברית (RTL) ועמוד באנגלית, לרביד קרודו, הנדסאי בניין רשום: בדק בית, בדיקה נגדית וחוות דעת הנדסית בצפון.
כל התוכן מבוסס על שאלון האפיון של רביד (22.10.2026), על האתר הקודם krudoeng.com ועל חוות דעת הנדסית של רביד (30.10.2026), שממנה נלקחו התואר, ההסמכה, הניסיון, הכתובת, שיטת העבודה והצילומים. שום לקוח, מספר, הסמכה או המלצה לא הומצאו.
העמודים נבנים מסקריפט: עורכים את `tools/content.py` ומריצים `python3 krudoeng/tools/build.py`.

## המבנה (גרסה 2, ארגון מחדש)
אתר בהיר ואדריכלי. הפס העליון, הפתיחה בדף הבית וסוף העמוד בפטרול של המותג, וכל השאר על לבן ועל נייר בהיר. כתום רק לכפתורי פעולה.
בלי אנימציות: כל התוכן גלוי מההתחלה. מידע ארוך עובר לשאלות שנפתחות, לעמוד השירות או לעמוד ייעודי.

**תפריט ראשי:** שירותים · ליקויים מהשטח · לעורכי דין ומתווכים · אודות · מאמרים ומדריכים · צור קשר, וכפתור וואטסאפ קבוע.
בטלפון התפריט נפתח למסך מלא: השירותים לפי שלושה מצבים (לפני שקונים, כשמקבלים מפתח, כשיש רטיבות, סדק או מחלוקת), ואחריהם שאר האתר.
**סוף העמוד:** כל השירותים, כל העמודים, פרטי קשר, נגישות ופרטיות.

**דף הבית, לפי הסדר:** פתיחה (צילום הבית מהאתר הקודם, כותרת, משפט, וואטסאפ וטלפון) · איזו בדיקה מתאימה לכם · למה רביד ·
איך זה עובד · מה בודקים בדירה (הדירה השקופה עם "מבט של בודק") · ליקויים מהשטח · דוח לדוגמה · רביד · שאלות נפוצות · תיאום בדיקה.

**עמוד שירות (תבנית אחת לשבעה):** פירורי לחם, כותרת, משפט וכפתורים, ולצידם "בקצרה" · מתי ולמה · מה בודקים (עם צילום מהשטח) ·
מה מקבלים ואיך זה עובד · שאלות · תיאום עם טופס מותאם · שירותים קרובים.

**ההדמיה (הדירה השקופה)**: דגם CSS 3D בלי ספריות (`assets/js/apartment.js`), באזור "מה בודקים בדירה" בדף הבית, ובפתיחה של העמוד באנגלית. היא לא זזה מעצמה.
"מבט של בודק" מדליק בה שבעה ממצאים: במחשב כולם יחד, ובטלפון אחד בכל פעם. בלי JavaScript מוצגת תמונה סטטית. הדירה והממצאים בה הם המחשה, וכך הם מסומנים באתר.

articles/  checklist/      מאמרים ומדריכים; רשימת בדיקה למקבלי דירה + assets/krudo-checklist.pdf

assets/css/site.css        כל העיצוב
assets/js/site.js          תפריט, מבט של בודק, טופס לוואטסאפ, הדפסה, מדידה

התיקייה `tools/` והקובץ הזה לא עולים ל-GitHub Pages (הוחרגו ב-`.github/workflows/pages.yml`).
כל התוכן, כולל התפריט, המצבים, "למה רביד" והתהליך, נמצא ב-`tools/content.py` (בסוף הקובץ: NAV, SITUATIONS, WHO, PROCESS, WHY, HOME2, SERVICES_PAGE).

## בנייה
```
python3 krudoeng/tools/build.py                      # כל העמודים
python3 -m http.server 8765                          # מתיקיית הריפו, בטרמינל נפרד
NODE_PATH=$(npm root -g) node krudoeng/tools/render.cjs && python3 krudoeng/tools/webp.py   # תמונות הדגם, תמונת השיתוף, PDF
```

## השקה (מתג אחד)
1. ב-`tools/build.py`: `LAUNCH = True`, ולהריץ. ה-noindex יורד, נוספים canonical ו-hreflang, ונוצרים `sitemap.xml` ו-`robots.txt` לכתובת https://www.krudoeng.com.
2. הדומיין רשום ב-GoDaddy. להעלות את תוכן התיקייה `krudoeng/` לשורש האחסון (Netlify / Cloudflare Pages / Vercel, או ריפו נפרד ב-GitHub Pages) ולכוון את ה-DNS.
   ב-Netlify/Cloudflare הקובץ `_redirects` נותן 301 אמיתיים מהכתובות הישנות (עם `301!`, כי באותן כתובות יש גם עמודי הפניה); בכל אחסון אחר העמודים בתיקיות העבריות עושים את אותו הדבר.
   להוציא את `krudoeng/` מהפריסה של GitHub Pages (`.github/workflows/pages.yml`), אחרת github.io ימשיך להציג עותק של האתר החי.
3. Google Search Console: לאמת את הדומיין, להגיש את ה-sitemap, ולבדוק אחרי שבועיים כתובות 404.
4. פרופיל העסק בגוגל: לעדכן את כתובת האתר.

## לאשר עם רביד לפני השקה
- **צילום הבית בפתיחה של דף הבית** (`assets/img/photo/house-*.webp`) נלקח מהכותרת של האתר הקודם. לפי מזהה הקובץ זה צילום מהמאגר של Wix, ולא קובץ שרביד העלה (הלוגו והתמונות שהוא העלה מסומנים אחרת), ותמונות מהמאגר של Wix מורשות לשימוש באתרי Wix בלבד. לפני השקה מחוץ ל-Wix: לקנות רישיון לצילום, או להחליף אותו בצילום של רביד באותם שמות קבצים.
- **הצילומים והעמוד לדוגמה מחוות הדעת (30.10.2026).** נחתכו כך שאין בהם שם, כתובת, תאריכים, עלויות התיק, שמות של מהנדסים אחרים או צילום של הבניין מבחוץ. לוודא שמותר לפרסם אותם. להסרה: לרוקן את `FIELD['items']`, ואז הדף, הרצועה בדף הבית, התמונות בעמודי השירות והעמוד לדוגמה חוזרים לבד להמחשה.
- התואר: באתר עכשיו "הנדסאי בניין רשום (מ.ר 38633308)", כמו בחוות הדעת ובהצהרה שבה (באתר הקודם: "מוסמך"; שאלה 31: "שילוב, אסביר בשיחה"). אין "מהנדס" בשום מקום.
- ההסמכה מהאיגוד: באתר "מאתר ליקויי בנייה מטעם איגוד המהנדסים", כמו בחוות הדעת. הנוסח של האתר הקודם ("הסמכה לכתיבת חוות דעת מומחה") הוסר.
- הכתובת: באתר "מעלה אבשלום 65, קריית טבעון" (נייר המכתבים של חוות הדעת). באתר הקודם: זבולון 6. לאשר שאפשר להציג אותה.
- מבנה הדוח: האתר מתאר לכל ממצא סעיף תקן, המלצה ותמחור לפי מחירון דקל, כמו בחוות הדעת. לוודא שגם דוחות בדק בית רגילים בנויים כך.
- מצלמה תרמית: מופיעה בשאלון, אבל לא ברשימת הציוד של חוות הדעת. לוודא שהיא בשימוש.
- "פיקוח הנדסי" מופיע בשורת התיאור של רביד. אם זה שירות שהוא מציע, אפשר להוסיף לו עמוד.
- English: האם רביד נותן שירות ודוח באנגלית (העמוד באנגלית לא מבטיח את זה).
- הניסוח על חוות דעת לבית משפט: "במתכונת של חוות דעת מומחה, עם הצהרת המומחה במקום עדות", כמו בחוות הדעת עצמה.
- תיאורי בדיקה נגדית, בית פרטי ושטחים משותפים, ורשימת הבדיקה למקבלי דירה: נכתבו כטיוטה.
- ההמלצה "משפחת ברק, כפר סבא" מהאתר הקודם לא הועברה: לא ברור אם היא אמיתית.
- מחירים: לא מוצגים (כך הובטח בשאלון). מוצג ההיגיון בלבד: לפי שטח בנוי, סוג והיקף.

## מדידה
`site.js` דוחף אירועים ל-`dataLayer`: `whatsapp_click`, `phone_click`, `form_submit`, `inspector_view`, `finding_open`, `vcard_download`, `checklist_download`, `sample_report_download`.
אין כרגע כלי מדידה ואין עוגיות (כך כתוב במדיניות הפרטיות). כשמוסיפים Google Tag Manager, לעדכן את מדיניות הפרטיות ואת ה-CSP ב-build.py.
העתק הפנייה במייל (`data-copy-to`, FormSubmit) כבוי. כשמפעילים אותו, להוסיף `https://formsubmit.co` ל-connect-src ב-CSP שב-build.py.

## אבטחה ונגישות
CSP קשיח בתגית meta (בלי inline script, מלבד שורה אחת עם hash), בלי משאבים חיצוניים, ו-`_headers` (frame-ancestors, nosniff) לאחסון שתומך בו. בלי JavaScript הטופס, התפריט ו"מבט של בודק" מוסתרים, ובמקום הטופס מופיע קישור וואטסאפ רגיל. ניווט מקלדת מלא, קישור דילוג, ניגודיות AA,
כיבוד "הפחתת תנועה", חלופה סטטית בלי JavaScript, טקסט חלופי, ותוויות לטופס. הצהרת נגישות ב-`accessibility/`.
