# סוכן מסחר טכני ל-Interactive Brokers

סוכן שרץ פעם ביום, מחשב איתותים טכניים על נרות יומיים, מעביר כל הוראה דרך מנהל סיכונים ושולח הוראות לימיט ל-IBKR.
**ברירת המחדל היא חשבון תרגול (paper) ומצב dry-run**, כך שבהתחלה שום הוראה לא נשלחת.

> אין כאן ייעוץ השקעות. אסטרטגיה טכנית יכולה להפסיד כסף, ותוצאות עבר לא מבטיחות כלום. צריך להריץ אותה על חשבון תרגול לפחות כמה חודשים לפני שחושבים על כסף אמיתי.

## האסטרטגיה (`agent/strategy.py`)
- **כניסה:** ממוצע נע 20 חוצה מעל ממוצע נע 50, ו-RSI(14) לא מעל 70.
- **יציאה:** ממוצע 20 חוצה מתחת ל-50, **או** סטופ נגרר: השיא מאז הכניסה פחות 3×ATR(14).
- רק לונג, נרות יומיים סגורים בלבד (הנר של היום, שעדיין לא נסגר, לא נכנס לחישוב).
- אותה פונקציה מריצה גם את הבקטסט וגם את הסוכן החי, אז מה שנבדק בבקטסט הוא מה שנסחר.

## הגנות
| הגנה | מה היא עושה |
|---|---|
| paper בלבד כברירת מחדל | במצב paper הסוכן מסרב להתחבר לפורט חי (7496/4001) או לחשבון שלא מתחיל ב-`D` |
| live דורש אישור כפול | `mode: live` בקונפיג **וגם** משתנה סביבה `CONFIRM_LIVE_TRADING=yes` |
| dry-run | מתחבר ל-IBKR במצב read-only, כך שה-API לא יכול לשלוח הוראות |
| לא נוגע בהחזקות שלך | הסוכן מוכר רק מניות שהוא עצמו קנה (`state/managed.json`) |
| גודל פוזיציה לפי תנודתיות | אם הסטופ נפגע, מפסידים בערך 1% מההון |
| תקרות | עד 20% לנייר, עד 80% חשיפה כוללת, לפחות 10% מזומן |
| עצירה יומית | אחרי ירידה של 3% ביום אין קניות חדשות (מכירות עדיין מותרות) |
| מגבלת הוראות | עד 10 הוראות ביום |
| רשימה סגורה | רק סימולים שמופיעים ב-`universe` |
| מתג חירום | יצירת הקובץ `state/STOP` עוצרת הכל |
| הוראות לימיט | מחיר מוגבל (±0.2%), ומה שלא בוצע תוך 30 שניות מבוטל |

## התקנה
1. פתחו **חשבון Paper Trading** ב-IBKR (Client Portal → Settings → Paper Trading Account).
2. התקינו **TWS** או **IB Gateway**, התחברו עם משתמש ה-paper.
3. ב-TWS: `File → Global Configuration → API → Settings`
   - סמנו *Enable ActiveX and Socket Clients*
   - פורט: `7497` (TWS paper) או `4002` (Gateway paper)
   - בשלב ה-dry-run מומלץ להשאיר גם *Read-Only API* מסומן
4. התקנת הקוד:
   ```bash
   cd trading-agent
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   cp config.example.yaml config.yaml   # ערכו סימולים ומגבלות
   ```

## שימוש
```bash
python run.py backtest -y 10        # בקטסט על נתוני Yahoo מול "קנה והחזק"
python run.py check                 # התחברות read-only, הדפסת חשבון ואיתותים
python run.py run                   # מעבר מסחר אחד (לפי dry_run בקונפיג)
python -m pytest -q                 # טסטים
```
כל החלטה נרשמת ב-`state/journal.csv`.

### הרצה יומית
הסוכן מיועד לרוץ פעם ביום, כ-15 דקות אחרי פתיחת המסחר בארה"ב (16:45 שעון ישראל ברוב השנה). TWS/Gateway צריכים להיות פתוחים ומחוברים. דוגמה ל-cron:
```
45 16 * * 1-5  cd /path/to/trading-agent && .venv/bin/python run.py run >> state/cron.log 2>&1
```
כניסה מתבצעת רק ביום החצייה עצמו. אם הסוכן לא רץ ביום הזה, הוא מחכה לחצייה הבאה ולא "רודף" אחרי מגמה שכבר רצה.

## תוכנית מעבר מדורגת
1. **בקטסט:** להבין את המספרים, כולל הירידה המקסימלית.
2. **paper + dry_run: true:** שבוע-שבועיים. לבדוק ב-journal שההחלטות הגיוניות.
3. **paper + dry_run: false:** לפחות 2–3 חודשים. להשוות ביצועים לבקטסט ול"קנה והחזק".
4. **live:** רק אם שלב 3 שכנע אותכם, עם סכום קטן ונפרד, ותקרות נמוכות יותר בקונפיג.

## מבנה
```
agent/strategy.py   אינדיקטורים + לוגיקת כניסה/יציאה
agent/risk.py       גודל פוזיציה ומגבלות סיכון
agent/broker.py     חיבור ל-IBKR (ib_async) + בדיקות בטיחות
agent/runner.py     מעבר אחד: נתונים → איתות → סיכון → הוראה → יומן
agent/state.py      מניות בניהול הסוכן, מונים יומיים, יומן
agent/backtest.py   בקטסט מול "קנה והחזק"
```
