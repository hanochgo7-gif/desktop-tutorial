# סוכן מסחר ל-Interactive Brokers: טכני + Claude

סוכן שרץ פעם ביום. בכל ריצה הוא מנקה את נתוני השוק ושומר אותם כ-point-in-time, מחשב איתותים טכניים, מעביר כל קנייה דרך מגבלות סיכון ודרך בדיקה של Claude (חדשות, אירועים ופנדמנטלי), שולח הוראות לימיט ל-IBKR ומציב עצירה אצל הברוקר.
**ברירת המחדל: חשבון תרגול (paper) ומצב dry-run**, כלומר בהתחלה שום הוראה לא נשלחת.

> אין כאן ייעוץ השקעות. הסוכן יכול להפסיד כסף, ותוצאות עבר לא מבטיחות כלום.

`SPEC_MAPPING.md` ממפה כל סעיף במסמך האפיון למימוש, או מסביר למה הוא לא מומש.

## מה הבדיקות הראו (קראו לפני הכל)
28 ניירות, 20 שנה (2007–2026, כולל 2008), עלויות מסחר, וריבית על כסף לא מושקע:

| | CAGR | ירידה מקסימלית | Sharpe |
|---|---|---|---|
| **הקונפיג המומלץ (50/200, trend)** | 6.3% | ‎-17.9% | 0.61 |
| קנה והחזק, אותם ניירות | 11.6% | ‎-45.2% | 0.64 |
| 60/40 | 8.1% | ‎-34.7% | 0.59 |

**האסטרטגיה מקטינה סיכון ולא מגדילה תשואה.** בבדיקת walk-forward, כוונון פרמטרים לפי העבר לא שיפר את התוצאה מחוץ למדגם. הגרסה המומלצת נבחרה מתוך כ-10 גרסאות, ולכן צפוי שבפועל היא תהיה מעט פחות טובה. פירוט ב-`SPEC_MAPPING.md`, סעיף 8.

## איך כל ריצה עובדת
```
מתג חירום? → ירידה מקסימלית מהשיא? (אם כן: מכירת הכל ועצירה)
→ circuit breaker (נפילה חדה של SPY? אין קניות היום)
→ לכל נייר: נתונים (ניקוי, בדיקת איכות, שמירה ל-PIT) → איתות
   ├─ יציאה: לפי חוקים בלבד (ביטול העצירה אצל הברוקר, ואז מכירה)
   ├─ מחזיק: העלאת העצירה אצל הברוקר (רק כלפי מעלה)
   └─ כניסה: מגבלות סיכון → Claude (אישור / הקטנה / ביטול) → קנייה → עצירה אצל הברוקר
→ רישום הון יומי → אזהרות סטייה → התראות
```

## האסטרטגיה (`agent/strategy.py`)
- **כניסה:** ממוצע נע מהיר מעל ממוצע איטי. במצב `cross` רק ביום החצייה. במצב `trend` בכל יום של מגמה, עם המתנה (cooldown) אחרי יציאה.
- **מסננים אופציונליים:** RSI, ‏SMA150 עולה (בסגנון מיכה סטוקס), ‏MACD, נפח, ומצב שוק (SPY מעל SMA200).
- **יציאה:** חציית הממוצעים כלפי מטה, או סטופ נגרר: השיא מאז הכניסה פחות מכפיל × ATR.
- רק לונג ורק נרות סגורים. אותה פונקציה מריצה את הבקטסט ואת הסוכן החי.

## Claude כבודק סיכונים (`agent/analyst.py`)
לפני כל קנייה Claude מקבל את האינדיקטורים ותמונה פנדמנטלית: P/E, צמיחה, מרווחים, חוב, תזרים ומועד הדוח הבא. אחר כך הוא מחפש ברשת אירועים קרובים וחדשות מהותיות.

| מותר ל-Claude | אסור ל-Claude |
|---|---|
| לאשר קנייה | להגדיל פוזיציה (המכפיל מוגבל ל-1) |
| לבטל קנייה (ואז אין בדיקה חוזרת של אותו נייר במשך 7 ימים) | ליזום עסקה |
| להקטין כמות | לעכב מכירה |

**עלות:** Claude נקרא רק לפני קנייה. במצב trend יש כ-4 כניסות בשנה לכל נייר (לפי הבקטסט), כך שבתיק של 10 ניירות מדובר בכ-40–60 בדיקות בשנה. כל בדיקה צפויה לעלות סנטים עד עשרות סנטים (הערכה, לא נמדד).

**כל כשל נחשב ביטול:** שגיאה, סירוב, תשובה לא ברורה או ביטחון נמוך. כל בדיקה נשמרת ב-`state/reviews/`. אי אפשר לבדוק את Claude בבקטסט, כי הוא יודע מה קרה בעבר. בודקים אותו רק בחשבון התרגול.

## הגנות
| הגנה | ברירת מחדל |
|---|---|
| חשבון תרגול בלבד, מסרב לפורט או חשבון אמיתי | `mode: paper` |
| כסף אמיתי דורש אישור כפול | `mode: live` + `CONFIRM_LIVE_TRADING=yes` |
| dry-run: חיבור לקריאה בלבד | `dry_run: true` |
| מוכר רק מניות שהסוכן עצמו קנה | `state/managed.json` |
| **עצירה אצל IBKR (GTC), עולה כל יום** | `broker_stop: true` |
| סיכון לעסקה (גודל לפי ATR) | ‏1% |
| תקרה לנייר / לחשיפה כוללת / מינימום מזומן | ‏20% / 80% / 10% |
| **ירידה מקסימלית מהשיא: מכירת הכל ועצירת הסוכן** | ‏20% |
| הפסד יומי: אין קניות | ‏3% |
| **Circuit breaker: אין קניות אחרי נפילה של SPY** | ‏5% |
| מקסימום הוראות ביום | ‏10 |
| בדיקת איכות נתונים (ספליט חשוד, נתונים ישנים): דילוג על הנייר | תמיד |
| המתנה לפני כניסה חוזרת אחרי יציאה, כולל יציאה בעצירה אצל הברוקר | ‏5 ימי מסחר |
| מתג חירום ידני | `touch state/STOP` |

## התקנה
1. פתחו **חשבון Paper Trading** ב-IBKR (Client Portal → Settings → Paper Trading Account).
2. התקינו **IB Gateway** (מומלץ לסוכן) או TWS, והתחברו עם משתמש ה-paper.
3. ב-Gateway/TWS: `Configure → Settings → API → Settings`
   - סמנו *Enable ActiveX and Socket Clients*
   - פורט: `4002` (Gateway paper) או `7497` (TWS paper). עדכנו את `ibkr.port` בהתאם
   - *Trusted IPs*: רק `127.0.0.1`
   - בשלב ה-dry-run השאירו *Read-Only API* מסומן. בטלו אותו כשעוברים ל-`dry_run: false`, אחרת הסוכן לא יוכל לשלוח הוראות
4. הקוד:
   ```bash
   cd trading-agent
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   cp config.example.yaml config.yaml          # ערכו סימולים ומגבלות
   export ANTHROPIC_API_KEY=sk-ant-...         # console.anthropic.com (או analyst.enabled: false)
   export TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=...   # אופציונלי: התראות לטלפון
   ```

## פקודות
```bash
python run.py backtest -y 20                     # לכל נייר + תיק, מול קנה-והחזק ו-60/40
python run.py compare -y 20 -v trend:entry_mode=trend -v stage2:trend_sma=150   # A/B
python run.py walkforward -y 20                  # בחירת פרמטרים מהעבר ובדיקה מחוץ למדגם
python run.py check                              # חיבור לקריאה בלבד, הצגת חשבון ואיתותים
python run.py run                                # ריצת מסחר אחת
python run.py report                             # NAV, ירידה, Sharpe חי, ביצועים, slippage, ביטולים
python -m pytest -q                              # 76 בדיקות
```

## תפעול
- **הרצה יומית:** כ-15 דקות אחרי פתיחת המסחר בארה"ב, בדרך כלל 16:45 שעון ישראל. שימו לב: בשבועות שבהם רק צד אחד עבר לשעון קיץ/חורף, השעה זזה. דוגמת cron (כשהשעון של המחשב מוגדר לשעון ישראל):
  ```
  45 16 * * 1-5  cd /path/to/trading-agent && .venv/bin/python run.py run >> state/cron.log 2>&1
  ```
- **IB Gateway מתנתק פעם ביום** ודורש התחברות מחדש אחת לשבוע. אפשר להשתמש ב-[IBC](https://github.com/IbcAlpha/IBC) להתחברות אוטומטית. אם ה-Gateway לא מחובר, הריצה נכשלת **וזה בסדר**: העצירות יושבות אצל IBKR כהוראות GTC.
- **מחשב:** מחשב ביתי שדלוק בשעות המסחר, או שרת VPS קטן. אין צורך בענן מורכב.
- **גיבוי:** גבו את `state/` (קבצים קטנים). אם הוא נמחק, הפוזיציות לא נעלמות, אבל הסוכן כבר לא יודע אילו מניות הוא קנה, ולכן לא ימכור אותן.
- **הפקדה או משיכה:** משיכה נראית לסוכן כמו ירידה בהון. **אחרי משיכה, מחקו את `state/peak.json`**, אחרת עצירת הירידה המקסימלית עלולה למכור הכל.
- **מכירה ידנית של מניה שהסוכן קנה:** בסדר. בריצה הבאה הסוכן מזהה שהפוזיציה ירדה ומעדכן את עצמו.

## אבטחה
- ה-API של IBKR פתוח רק ל-`127.0.0.1`. אל תפתחו את הפורט לרשת.
- מפתחות (Anthropic, טלגרם) נשמרים במשתני סביבה, לא בקוד ולא ב-git. `config.yaml` ו-`state/` לא נשמרים ב-git.
- הפעילו 2FA בחשבון IBKR (IB Key).
- בכסף אמיתי: פתחו תת-חשבון נפרד לסוכן, עם סכום שאתם מוכנים להפסיד.
- **שימו לב:** אם הקוד נמצא ב-repo של האתר, דחיפה ל-`main` מפרסמת אותו ב-GitHub Pages. עדיף להעביר אותו ל-repo פרטי.

## מס (ישראל) – כדאי לבדוק מול רואה חשבון
- רווח הון ממניות לתושב ישראל מחויב בדרך כלל ב-25% על הרווח הריאלי, וגם דיבידנדים.
- ברוקר זר לא תמיד מנכה מס ישראלי במקור. אם לא נוכה, צריך לדווח בעצמכם בדוח שנתי (כולל נספח רווחי הון). ‏`state/journal.csv` מתעד כל עסקה.
- מסחר בתדירות גבוהה מאוד עלול להיחשב "עסק" ולהתחייב במס שולי. הסוכן הזה סוחר מעט (כמה עסקאות בשנה לכל נייר), אבל כדאי לוודא.

## תוכנית מעבר מדורגת
1. **בקטסט ו-walk-forward:** להבין את המספרים, במיוחד את הירידה המקסימלית.
2. **paper + `dry_run: true`:** שבוע-שבועיים. לעבור על ה-journal ועל `state/reviews/`.
3. **paper + `dry_run: false`:** לפחות 2–3 חודשים. להריץ `report` כל שבוע ולהשוות לבקטסט.
4. **live:** רק אם שלב 3 שכנע. תת-חשבון, סכום קטן, ותקרות נמוכות יותר.
